# CLAUDE.md — MotrWorks

Operational guidance for Claude Code sessions in this repository. Durable facts only.

## Purpose

MotrWorks (branded "MotrSynth — CortexEdge Engineering Tools" in the README; the app and design
files say `motrworks`) is a single-page electric-machine design tool. Six machine types —
BLDC/PMSM, brushed PM DC, limited-angle torquer (LATM), 2-phase hybrid/PM stepper, power-off
spring-applied brake, squirrel-cage ACIM — plus two composition modules: Actuator
(motor + brake + multi-stage planetary/spur/harmonic gearhead) and Winding (bobbin/arbor tooling).
Also: envelope-synthesis wizard, bench calibration, DXF lamination import/export, FEMM Lua export,
PNG/SVG export, localStorage autosave + undo, JSON design files.

Runs entirely client-side from `file://` or static hosting. No server, no CDN, no network calls.

## Architecture and module map

Ship artifact: **`index.html`** (~1.2 MB) — one self-contained file with an inlined React runtime
and the whole app. Structure, in order:

    <script>          startup error handler
    <script>/*RB*/    prebuilt React + ReactDOM runtime bundle (never regenerated by build.py)
    <script>/*APP*/   the app — the ONLY region the build rewrites
    <script>/*BOOT*/  createRoot(...).render(MotorDesigner)

Source of truth is `src/`, five modules concatenated in numeric order (no bundler):

| File | Contents |
|---|---|
| `src/01-shared.jsx` | materials (MAGNETS/STEELS/BRAKE_MATS/GEAR_MATS/BARS), wire tables, `PRESETS` (33), theme, unit context |
| `src/02-engine.js` | `computeDesign` (physics, pure), `computeBobbin`/`solveBobbin`, `designGearTrain`, `composeActuator`, DXF/FEMM builders |
| `src/03-dxf-import.js` | `parseDxf` + `analyzeLam` (lamination geometry inference) |
| `src/04-views.jsx` | ~32 SVG views, charts, drawings, input controls |
| `src/05-app.jsx` | `MotorDesigner` app shell: default state, tabs, cards, envelope wizard `synthEnvelope`, file IO |

Tabs: BLDC · Brushed · LATM · Step · ACIM · Brake · Actuator · Winding.

## Edit surface — source of truth vs generated

**Edit only:** `src/01-shared.jsx`, `src/02-engine.js`, `src/03-dxf-import.js`, `src/04-views.jsx`,
`src/05-app.jsx`, `tools/*`, `docs/*`, `build.py`, `README.md`.

**Never edit directly:**

- `index.html` — generated. Its `/*APP*/` block is overwritten by `build.py`. Verified: it
  reproduces byte-for-byte from `src/`. Hand edits are silently lost on the next build.
- `src/motor-designer.concat.jsx` — generated. Exactly the five modules concatenated in order with
  each module's leading `/* MotrWorks module NN … */` header line stripped. No script emits it;
  regenerate it by hand whenever `src/` changes so the committed copy stays in sync
  (`build.py` does *not* write it).
- `src/motor-designer.jsx` — **stale legacy monolith** (128 KB, last touched in the second commit,
  still branded "MotrSynth"). Not built, not tested, not loaded. Do not edit it and do not read it
  as current behavior. Removal is a housekeeping decision for the owner, not a side effect.

Build byproducts `_appsrc.tsx` / `_appsrc.js` are written to the repo root by `build.py` and are
covered by `.gitignore`. Do not commit them.

## Build

    python3 build.py        # from repo root; rewrites index.html in place

Requires `python3` and `tsc` on PATH (`npm i -g typescript`). `build.py` concatenates the five
modules, strips module headers, rewrites the React import into a destructure, drops
`export default` from `MotorDesigner`, transpiles with
`tsc --noCheck --jsx react --target es2020 --skipLibCheck`, and splices the result between the
`/*APP*/` and `/*BOOT*/` markers. It never touches the React runtime block.

Any `src/` change is not shipped until `build.py` runs and `index.html` is committed.

## Validation / gates / tests

Gates read the **built `index.html`**, extract the `/*APP*/` block, and evaluate it — so build
before gating. They are session-portable in intent but carry hardcoded absolute paths; stage the
environment first:

    # one-time env prep (NOT repo changes)
    npm install --prefix /home/claude/.npm-global/lib react@18 react-dom@18
    ln -sfn <repo> /home/claude/motrsynth/motrsynth          # golden-gate reads this path
    ln -sfn <repo>/index.html /home/claude/motrsynth/index.html   # e2e loads this file:// URL
    ln -sfn $(npm root -g)/playwright /home/claude/.npm-global/lib/node_modules/playwright
    cp tools/_base.json /tmp/_base.json                      # every gate reads /tmp/_base.json

Run from the repo root:

    node tools/ssr-gate.mjs          # REQUIRED before any deploy — SSR of the shipped block
    node tools/golden-gate.mjs       # frozen physics anchors, ±1% — the drift detector
    node tools/brushed-gate.mjs  tools/dxf-gate.mjs  tools/latm-gate.mjs  tools/latm-preset-gate.mjs
    node tools/stp-gate.mjs  tools/stp-preset-gate.mjs  tools/wind-gate.mjs
    node tools/brk-gate.mjs  tools/brk-preset-gate.mjs  tools/env-gate.mjs
    node tools/act-gate.mjs  tools/bob-gate.mjs
    # e2e (Playwright/Chromium against file://index.html)
    node tools/toggle-test.mjs  tools/stp-e2e.mjs  tools/filter-e2e.mjs
    node tools/latm-e2e.mjs  tools/wind-e2e.mjs  tools/brk-e2e.mjs

`brk-tune3.mjs` and `brk-render.mjs` are tuning/rendering utilities, not gates. There is no CI —
no `.github/` workflows exist. Gates are run by hand.

**Before release:** rebuild, regenerate the concat file, then run all 14 compute gates and all 6
e2e tests. **The full 20-test suite passes on `main` as of the v59.2 baseline — treat any failure
as a real regression, not as expected noise.** Commit `src/` + `index.html` +
`src/motor-designer.concat.jsx` together.

One known cosmetic wart: `wind-gate.mjs` prints `default SSR: <n> (changed — check)` because it
compares against an older hardcoded baseline. It still exits 0. Do not "fix" it by re-anchoring
unless you have a reason to touch that gate.

## Deployment

Static: GitHub Pages serving `main` at repo root (per README; no workflow file in-repo to confirm).
`index.html` is the deployed artifact — a commit that changes `src/` without a rebuilt `index.html`
ships nothing. The page works offline from `file://`; the only external reference is a favicon URL,
which degrades harmlessly.

## Git workflow and safety

- Work on the assigned feature branch. Never commit or push to `main`. Never merge.
- `index.html` changes on nearly every commit — that is expected (it is the built artifact), not
  noise to suppress.
- Do not "clean up" unrelated files, reformat untouched modules, or delete the stale legacy
  monolith without being asked.
- Do not change the build system (`build.py`, marker names, module order) as a side effect.

## Architectural constraints to preserve

- **Self-contained single file.** No bundler, no package.json, no CDN, no runtime network access.
  Anything added must inline into `index.html`.
- **Concatenation order matters.** Modules share one scope; a symbol must be defined in a
  lower-numbered module than its first use.
- **Pure, gate-testable cores.** `computeDesign`, `computeBobbin`, `solveBobbin`,
  `designGearTrain`, `composeActuator`, `synthEnvelope`, `activeAssumptions` take plain objects and
  return plain objects. Keep them free of React, DOM, and I/O — the gates instantiate them directly.
- **`computeDesign` must never throw.** Invalid input returns `{ err: [...] }` / `warnings`.
- **SSR-clean views.** Every view must render under `react-dom/server` with no DOM, no
  `window`/`document` access at render time, and no `NaN`/`undefined` in emitted geometry.
- **mm-canonical internals, unit-aware display.** The engine works in millimetres; inch is a
  display/entry conversion (`UnitCtx`, default inch). Never store display units in state.
- **Design files stay loadable.** JSON is `{ tool: "motrworks", version: 10, … }`; imports merge
  over defaults, unknown keys are ignored, and legacy shapes auto-migrate. Renaming or repurposing
  a state key requires a migration path. Actuator files are module-scoped (`scope: "actuator"`) and
  must never leak motor fields.
- **JSX text needs real characters.** `\uXXXX` escapes do not decode in JSX text nodes — use the
  literal character or `{\`…\`}`. This has caused shipped rendering bugs more than once.
- **Keep `tools/_base.json` in sync.** It holds non-geometry defaults only (each gate supplies its
  own machine geometry). A parameter added to app state and consumed by the engine but missing here
  silently becomes `NaN` in gate runs.

## Numerical and modeling correctness

- `tools/golden-gate.mjs` freezes analytical anchors (Kt, no-load, R L-L, peak torque) per machine
  type at ±1%. These are **drift detectors, not catalog truth**.
- An intentional model change *should* trip it. When it does: update the anchor **in the same
  commit**, and record what moved and why in `docs/audit-v58.md`. Never widen a band to hide drift,
  and never re-anchor without stating the physical reason.
- Physics changes need a stated basis — a bench measurement, a catalog anchor, a FEMM solve, or an
  explicit first-order derivation. Say which one.
- Preserve honest disclosure: where the model is approximate, the app says so in-card. Do not
  remove or soften those notes, and add one when introducing a new approximation.
- Calibration factors, wire tables, material tables, and preset values are engineering data. Do not
  adjust them to make a test pass.

## Working rules

- **Separate verified facts from assumptions.** State what you ran and observed versus what you
  inferred. "The gate prints X" and "this probably means Y" are different claims; label them.
  Do not treat `docs/` narrative or README text as verified current behavior — check the code.
- **Stop and ask before major architectural change.** Introducing a bundler or package manager,
  splitting or reordering modules, changing the build markers or pipeline, restructuring app state
  or the design-file format, removing a machine type or module, deleting legacy/generated files, or
  re-anchoring golden-gate for a non-obvious reason — all need the owner's decision first.
