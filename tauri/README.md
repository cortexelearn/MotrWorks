# MotrWorks — Tauri desktop shell

Wraps the MotrWorks single-file app in a native Windows executable so it can
be installed and run without a browser or any hosting.

It is a **shell, not a fork**: the exe embeds the repo-root `index.html` —
the same committed artifact GitHub Pages serves — so the desktop build and
the browser build are the identical application. Nothing under `src/` and
nothing in the `build.py` pipeline changes to build this.

## Prerequisites (Windows)

- **Rust** (stable MSVC toolchain) — <https://rustup.rs>
- **Visual Studio 2022 Build Tools** with the *Desktop development with C++*
  workload (supplies the MSVC linker and Windows SDK)
- **Node.js 18+**
- **WebView2 runtime** — present on Windows 10/11 by default; the installer
  produced here also carries a bootstrapper for machines that lack it

Verify with `npx tauri info` from this directory — every entry under
*Environment* should be green.

## Build

```powershell
cd tauri
npm install       # the Tauri CLI (the app itself has no npm dependencies)
npm run build
```

Outputs, relative to `tauri/src-tauri/target/release/`:

| Artifact | Path |
| --- | --- |
| Standalone executable | `motrworks.exe` (named from the Cargo package, not productName) |
| NSIS installer | `bundle/nsis/MotrWorks_<version>_x64-setup.exe` |

`motrworks.exe` is self-contained apart from the WebView2 runtime — the whole
frontend is embedded in the binary. It can be copied to another machine as-is.

## What `npm run build` actually does

1. **`npm run stage`** (`scripts/stage.js`) copies the repo-root `index.html`
   into `tauri/dist/` — a single-file copy, since the app is fully
   self-contained. It stages the **committed** artifact; it does not run
   `build.py`. If you changed `src/`, run `python3 build.py` at the repo root
   first, or the exe ships the stale build.
2. **`tauri build`** compiles `src-tauri` and embeds `../dist` into the
   binary, then produces the NSIS installer.

`tauri/dist/`, `node_modules/`, `src-tauri/target/` and `src-tauri/gen/` are
all generated and git-ignored.

## Layout

```
tauri/
  package.json              npm scripts + the Tauri CLI (pinned via package-lock.json)
  scripts/stage.js          copies ../index.html into tauri/dist/ for embedding
  scripts/make-icons.js     regenerates src-tauri/icons/* (dependency-free; run only if the mark changes)
  src-tauri/
    Cargo.toml              size-optimised release profile
    tauri.conf.json         window, bundle and security config
    capabilities/default.json
    src/main.rs             builds the window; no commands registered
    icons/                  committed, generated by scripts/make-icons.js
```

## Desktop-specific behaviour

- **localStorage autosave persists.** The webview origin is
  `http://tauri.localhost`, and WebView2 stores its profile (including
  localStorage) under the app's data directory — so the autosave/undo that
  works in a browser works here too, and survives relaunches. Deleting the
  app's WebView2 data folder (under `%LOCALAPPDATA%\com.cortexelearn.motrworks`)
  resets it, same as clearing site data in a browser.
- **File IO is browser-native and WebView2 handles it.** Design JSON import
  and DXF import use `<input type=file>`, which opens the normal OS file
  picker. Exports (design JSON, DXF, FEMM Lua, PNG/SVG) are blob
  `a[download]` clicks, which WebView2 routes through its download flow into
  the user's Downloads folder. Exercise design-JSON and DXF export once in
  the built exe as a smoke test — this is standard WebView2 behaviour but has
  not been individually verified here.
- **The favicon reference is inert.** `index.html` carries one external
  favicon URL; the desktop window icon comes from the bundle icons, and the
  fetch failing offline is harmless. This is the app's only external
  reference — nothing else leaves the machine.

## Security posture

Unchanged from the browser build:

- The capability set is `core:default` only — no filesystem, shell, http or
  dialog permissions are granted to the frontend.
- `assetProtocol` is disabled; the frontend is served from the embedded bundle.
- No Tauri command is exposed — `src/main.rs` registers no `invoke_handler`.
- The bundle contains the staged `index.html` and nothing else.
- The app makes zero network calls (favicon aside); React is inlined, not
  fetched. After install it runs fully offline.
